轉譜架構選擇

共同要求：圖片、PDF、MusicXML 輸入；首調預設（小調主音記 6）；依要求可固定音高；輸出文字、可列印 PDF、MusicXML 與 MIDI。

A. Agent 直接識譜

輸入
圖片 / PDF → AI 視覺判讀 → 簡譜文字 / PDF

優點：依賴少，特殊版面彈性高。

風險：音高、節奏、聲部對齊與 MIDI 難以自動驗證，結果不易重現。

定位：無法執行 repo 工具時的降級模式，不作為唯一準確性保障。

B. 只擴充既有 Pipeline

輸入
圖片 / PDF → Audiveris → MusicXML → 擴充現有轉換器

優點：沿用既有 CLI、OMR 與 MusicXML/MIDI 元件。

風險：現有轉換會攤平音符；若只修補 token 轉換，難以穩定保留聲部、拍位、歌詞、tie 與排版。

定位：比現狀完整，但仍需明確的標準資料模型。

C. 標準 Score Model 混合流程（建議）

任一輸入
圖片 / PDF → OMR；MusicXML → 直接解析
→ Score Model（聲部、實際音高、拍位、時值、休止、歌詞、tie）
→ 節拍／音高／歌詞驗證與不確定項確認
→ 首調或固定音高 → 簡譜文字 + ReportLab PDF + MusicXML + MIDI

優點：一份有型別的中介資料驅動所有輸出；各層可用黃金資料測試。

成本：建立資料模型、音高映射、簡譜排版器與語義測試，工作量較大。

定位：同時滿足精度、可重現性與通用 Agent Skill 的最穩健方案。

建議驗證閘門：任何低信心音符或模糊臨時記號先標出小節／聲部／候選音，不可猜填；確認前不宣稱完整準確。語義測試應比較完整事件（實際音高、起拍、時值、聲部、歌詞），不只確認輸出檔存在。

新增基準譜是 6 頁 SATBB 五聲部原譜；Spark 輸出另有主旋律頁。需確認這是刻意的額外交付，還是多生成了原譜沒有的內容。
